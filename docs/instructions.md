# Update Protocol

When the trigger phrase `update-protocol` is entered, review the current codebase and update all relevant project documentation.

## Required actions

1. Review the completed code and identify any changes that need to be documented.
2. Update the existing project documentation files, including:
   - ClearGuide.txt
   - Documentation.txt
3. If additional documentation is needed, create new .txt files with clear names and specific purposes.
4. Store all supporting documentation in a separate documentation folder so it does not clutter the main project files.
5. Keep the main project root limited to the README and any required code or image assets unless another location is explicitly requested.

## Documentation standards

- Use clear, readable, plain-text documentation.
- Include summaries of new features, updates, setup steps, and project structure.
- Ensure files are organized logically and named in a way that is understandable to other team members.
- Keep documentation accurate and aligned with the current code.

## User guide and troubleshooting

The update-protocol must also include:

- A user guide for the software
- A basic troubleshooting guide

These guides should explain how to use the software, common issues, and simple solutions for users.

## PDF conversion

All text-based documentation should later be converted into PDF format for distribution or archiving.

## Final rule

If a documentation file is outdated, incomplete, or missing, it must be updated or created as part of the update-protocol process.
